# bondova-MOR Project Guide

**Last Updated:** 2026-09-23

## Vision

bondova-MOR is a system designed to:
1. Receive ideas generated by **Skape** (external ideas source)
2. Analyze those ideas using our custom-built **Analysis Motor**
3. Store and manage analysis results for further use

## Project Name Meaning

- **bondova** - Project identifier
- **MOR** - Motor Operation and Research (our custom analysis system)

## Architecture Overview

```
Skape (Ideas Source)
    ↓
    ├─→ [Skape Adapter] - Normalize incoming ideas
    │
    ↓
[Analysis Motor] - Core analysis engine
    │
    ├─→ Processing Pipeline
    ├─→ Idea Evaluation
    ├─→ Result Generation
    │
    ↓
[Storage Layer] - Persist results
    │
    ├─→ Database (TBD: Supabase/PostgreSQL/etc)
    ├─→ State Management
    ├─→ Query Interface
    │
    ↓
Output (Analysis Results)
```

## Core Components

### 1. Skape Adapter (`src/skape-adapter/`)
- Interface for receiving ideas from Skape
- Data validation and normalization
- Error handling for malformed input
- Transforms external format → internal format

### 2. Analysis Motor (`src/motor/`)
- Core analysis logic and algorithms
- Processing pipeline orchestration
- Extensible for different analysis types
- Performance optimized for batch and real-time processing

### 3. Storage Layer (`src/storage/`)
- Database abstraction layer
- State persistence
- Query interface for retrieving analysis results
- Transaction support where needed

## Data Flow

1. Skape generates an idea and submits via Adapter
2. Adapter validates and normalizes the idea
3. Motor receives normalized idea
4. Motor executes analysis pipeline
5. Results stored in database
6. Results available for querying and further processing

## Environment Variables

Configuration via environment variables (see `.env.example`):

- `NODE_ENV` - Environment (development/production/test)
- `DATABASE_URL` - Database connection string
- `SKAPE_API_KEY` - API key for Skape integration (if applicable)
- `MOTOR_CONFIG` - Motor-specific configuration

## Getting Started

1. Clone the repository
2. Install dependencies: `npm install`
3. Copy `.env.example` to `.env.local` and fill in values
4. Run tests: `npm test`
5. Start development: `npm start` or `npm run dev`

## Testing Strategy

- Unit tests for individual components
- Integration tests for data flow between components
- End-to-end tests for complete idea processing
- Test files in `tests/` directory mirroring `src/` structure
